# Отчёт: демонстрация механизма Rollback

## 1. Цель работы

Целью данной части лабораторной работы является демонстрация механизма отката приложения к предыдущей рабочей версии в случае возникновения ошибки при запуске новой версии.

## 2. Описание реализации

Для демонстрации были подготовлены два Docker-образа:

- `lab03-rollback-broken` — неисправная версия приложения. При запуске контейнера процесс завершается с кодом ошибки 1.
- `lab03-rollback-good` — рабочая версия приложения, собранная на основе основного Dockerfile лабораторной работы.

Неисправная версия использовалась для имитации ситуации, когда после обновления приложение перестаёт запускаться.

## 3. Проверка неисправной версии

После сборки и запуска неисправного Docker-образа контейнер завершил работу со статусом `Exited (1)`.

При попытке обратиться к endpoint `/health` сервер оказался недоступен. Это подтвердило, что неисправная версия приложения не может обслуживать запросы.

## 4. Выполнение отката

Для восстановления работоспособности был подготовлен PowerShell-скрипт `rollback.ps1`.

Скрипт выполняет следующие действия:

1. Проверяет наличие ранее запущенного рабочего контейнера.
2. Удаляет старый контейнер, если он существует.
3. Запускает новый контейнер на основе рабочего Docker-образа.
4. Выполняет повторные запросы к endpoint `/health`, ожидая готовности приложения.
5. Выводит результат восстановления и затраченное время.

При успешном выполнении скрипт выводит сообщение `Rollback successful!`.

*Рисунок 3 — Успешное выполнение скрипта отката.*

## 5. Проверка восстановленной версии

После выполнения отката endpoint `/health` вернул ответ:

```json
{"status":"ok"}
```

HTTP-статус ответа — `200 OK`. Это подтверждает, что приложение восстановлено и снова обрабатывает запросы.

Время восстановления при последнем запуске скрипта составило **1,80 секунды**.

## 6. Вывод

В ходе выполнения дополнительной части лабораторной работы была продемонстрирована работа механизма Rollback с использованием Docker и PowerShell.

Была смоделирована ситуация отказа приложения, после чего выполнено восстановление предыдущей рабочей версии. Работоспособность восстановленного приложения подтверждена успешным ответом endpoint `/health`.

Таким образом, механизм отката позволяет быстро вернуть приложение к рабочему состоянию в случае возникновения проблем после обновления. В данной работе восстановление выполнялось локально и вручную с помощью PowerShell-скрипта.
