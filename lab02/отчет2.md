## Плохой Dockerfile | Я плохая - ты хороший 
Докерфаийл это наша инструкция, по которой докер собирает образ и в этом блоке я в этой инструкции напакостила: 

FROM python:latest - не закреплена конкретная версия питона. При повторной сборке базовый образ может измениться, что затрудняет воспроизводимость.

USER root	- приложение запускается от имени рута. Это увеличивает потенциальный ущерб при взломе приложения, потому что обычный пользователь может почувствовать власть с таким количеством прав внутри нашего контейнера, а нам такого не надо. 

RUN apt-get update && apt-get install -y build-essential - устанавливаются инструменты сборки, которые не нужны для обычного запуска приложения, но остаются в итоговом образе и увеличивают его размер.

COPY . . перед установкой библиотек -	копируются все файлы проекта. Изменение любого скопированного файла может сделать кэш слоя с установкой зависимостей недействительным и замедлить пересборку.

Нет HEALTHCHECK	- докер не выполняет специальную проверку, отвечает ли приложение (связь?). Сам контейнер может числиться работающим, даже если приложение перестало нормально обслуживать запросы, а мертвые души нам не нужны.

Нет .dockerignore	- докер может отправить в контекст сборки ненужные файлы, например .git, документацию и локальные артефакты. Это увеличивает контекст сборки и создаёт риск случайного включения секретов.

Вообще отдельное указание на то, что юзер это рут не было необходимо, потому что если про юзера и вовсе не упомянуть, то он будет числиться рутом, но если пакостничать, то пакостничать по-крупному, поэтому я явно указала принадлежность юзера к руту

## Docker Compose | Вас заперли в докер контейнере - ваши действия?
Для следующих манипуляций я воспользовалась nginx чтобы связать фронт, бэк и базы данных для взаимодействия с ежедневником через одну точку. Он отдаёт файлы сайта и направляет API-запросы нужному контейнеру. 
- include /etc/nginx/mime.types — подключает таблицу типов файлов. Благодаря ей браузер понимает, что CSS — это стили, JavaScript — это скрипт, а HTML — веб-страница
- default_type application/octet-stream — тип содержимого по умолчанию, если подходящий тип не найден
- listen 80 - Nginx принимает HTTP-запросы на порту 80
- root /usr/share/nginx/html — отсюда Nginx отдаёт файлы сайта
- location / — обрабатывает запросы к страницам и статическим файлам, try_files проверяет, существует ли запрошенный файл или каталог,если ничего не найдено, nginx возвращает ошибку 404 
- location /api/ — перенаправляет запросы к backend
- proxy_pass http://backend:5000/ — обращается к сервису backend на порту 5000. Имя backend будет задано в Docker Compose

Фронт собирается с помощью Dockerfile.frontend и доступен на порту 8080. Бэк собирается из хорошего образа Dockerfile.good и получает параметры подключения к базе данных через переменные окружения.
